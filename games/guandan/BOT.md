# 掼蛋 bot 对打与复测

比较两个版本时，用同一副牌交换两队各打一局。记录哪队拿到头游，也记它最终升了几级。下面的命令在仓库根目录运行，依赖用 `npm ci` 安装。

## 和 DanZero 打，再复盘失分的那一手

**2026-11-29 本地结果。** 两批独立牌上，新版合计比旧版多赢 69 局。每个种子由双方换座打两次，胜率指拿到头游的比例，净升级按赢加 1–3、输减 1–3 计算。比较两版时先在同一种子的两局内取平均，再用种子之间的差异估计 95% 区间。

| 对 DanZero 的验收牌 | 旧版胜场 | 新版胜场 | 胜率差（百分点，约 95% 区间） | 每局净升级差（约 95% 区间） |
| --- | ---: | ---: | ---: | ---: |
| 970000–970623 | 808/1248 | 820/1248 | +0.96（−0.37 至 +2.29） | +0.061（+0.002 至 +0.120） |
| 1000000–1001247 | 1579/2496 | 1636/2496 | +2.28（+1.31 至 +3.26） | +0.104（+0.061 至 +0.147） |
| 合计 | 2387/3744（63.76%） | 2456/3744（65.60%） | **+1.84（+1.05 至 +2.63）** | **+0.090（+0.055 至 +0.124）** |

第二批在看到第一批结果后确定全批种子数，策略保持冻结。两批共 1,872 个种子，每种级牌 144 个。对照相同牌和座次，153 局从输变赢，84 局从赢变输；平均净升级从 +0.849 提到 +0.939。两版的 7,488 份回放都通过了规则引擎的逐步合法性检查和独立重算结算。开发阶段用于选策略的种子（包含后文的三局复盘）全部排除在表外。

本轮使用 DanZero 原作者公开的 567 维 Q 网络。凑局按自己的规则发牌，双方只收到当前座位的视图。对手自行枚举出法，按网络评分选牌。先装好[本地 DanZero 对手](scripts/opponents/danzero/README.md)。权重由开发者单独取得，玩家浏览器只运行 TypeScript。

本轮旧版为 `97d99a4`（策略 `022dc80`），新版为 `ea46b7d`，DanZero 适配器为 `public-rebuild-v3.1`。它在 49 个公开局面上重现了上游全部 567 维特征；50 个局面、1,007 个候选的 NumPy 和原 PyTorch 选牌一致。同花顺在这个对手的动作空间里只按同花顺声明。第三方公开评测中，DanZero 对南邮规则选手取得过 71.4% 的单副胜率；下文凑局的成绩均来自本机实打。[上游实现](https://github.com/Choysang/rlcard-guandan/tree/6ebe65a14a0bfe6140df9f231e7bf4a340c94f34) · [DanLM 作者的对战记录](https://github.com/dashidhy/DanLM#results)

在 Bash 中复跑下列命令。每个输出文件都要求是新文件，防止覆盖回放。种子相同会得到相同的牌、首家和级牌；级牌从 2 到 A 轮换。

```sh
lab=games/guandan/.baseline/recheck
scripts=games/guandan/scripts
opponent=$scripts/opponents/danzero/opponent.mjs
mkdir -p "$lab/base"
git archive 97d99a4 games/guandan/src | tar -xf - -C "$lab/base" --strip-components=3 --exclude='*.test.*'
node "$scripts/opponent-arena.ts" "$opponent" 924000 52 "$lab/before.jsonl" "$lab/base/searchbot.ts"
node "$scripts/opponent-arena.ts" "$opponent" 924000 52 "$lab/after.jsonl"
node "$scripts/opponent-results.ts" "$lab/after.jsonl" "$lab/before.jsonl"
```

**哪些出牌丢了级分。** 以下三例都先让原版和 DanZero 从头逐手重现原回放，再只替换指定一步，后面双方按原策略打完。步号从 0 开始。它们是用来找问题的开发牌。

| 种子、级牌 | 原版怎么打 | 只换这一手后的结果 |
| --- | --- | --- |
| 924022，打 10，第 31 步 | 对手出对 J，我方手里有对 K，选择过牌 | 用对 K 接，输 2 级变为赢 3 级 |
| 924023，打 J，第 2 步 | 对手出三个 9 带对 2，我方用了两张红桃 J，配成三个 10 带对 8 | 过牌保留两张配牌，输 3 级变为赢 2 级 |
| 924031，打 6，第 59 步 | 对手出单 3，我方最后一张 K 能拿头游，搜索却选了过 | 出 K，输 1 级变为赢 2 级 |

```sh
node "$scripts/opponent-replay.ts" "$opponent" "$lab/before.jsonl" 924022 1 31 '{"type":"play","cards":["S13b","D13b"],"as":{"kind":"pair","main":13}}' "$lab/base/searchbot.ts"
node "$scripts/opponent-replay.ts" "$opponent" "$lab/before.jsonl" 924023 1 2 '{"type":"pass"}' "$lab/base/searchbot.ts"
node "$scripts/opponent-replay.ts" "$opponent" "$lab/before.jsonl" 924031 0 59 '{"type":"play","cards":["C13a"],"as":{"kind":"single","main":13}}' "$lab/base/searchbot.ts"
```

**策略怎么改。** 全桌还剩 50 张以上时，遇到对手的普通牌，分别估计跟牌和过牌的终局净升级差。评分考虑剩牌能拆成几手、是否动用配牌或拆炸、桌外还剩多少大牌、对家是否还有一次接牌机会。两种选择预估相差超过 0.2 级才改变原策略。对手出单时，自己能用最后一张拿头游会直接出完。对家已经头游能锁定双上，或只剩两家时能锁定三游，也直接出完。

评分器用 2,400 副规则自对弈和 600 副对 DanZero 的训练牌拟合。每个局面从同一副牌分两路打到底，双方决策用各自的公开视图，16,403 组净升级差作为标签。级牌、种子、原版策略和对手版本都固定。复算完整权重可以按种子分片，最后把所有分片传给 `fit`。

```sh
node "$scripts/train-contest.ts" sample "$lab/base/bot.ts" rule 720000 2400 "$lab/train-rule.json"
node "$scripts/train-contest.ts" sample "$lab/base/bot.ts" "$opponent" 917000 600 "$lab/train-danzero.json"
node "$scripts/train-contest.ts" fit 75 "$lab/train-rule.json" "$lab/train-danzero.json"
```

**取舍和验证。** 保护级牌对、提前对普通跟牌做浅搜索、手调接高对和让三带二的阈值，都试过独立对局。手调组合在开发牌上多赢 4 局，但换 52 局新牌后双方都是 29 胜，净分还少 3 级。另一个两家明牌残局的完备搜索检查了 728 局中的 834 个真实决策，唯一一手能改成保证三游的局面，原版对实际对手也已经拿到三游。这些改法留作本地实验。

在 1,472 个相同的早中盘跟牌局面上交替测新旧牌桌入口，桌面 Node 的单步 P95 从 0.68 ms 到 1.02 ms。用 4 场完整升级赛检查进贡、还贡和过 A，一共打了 48 副、57 次进贡、57 次还贡和 6 次抗贡。这 4 场只用于流程验证。本地 CI 通过 310 项测试，桌面和 360、412 像素手机视口也各打完了一副。

**换个对手。** 新旧版直接交手，覆盖打 2 到打 A，每种级牌 20 个种子换座。新版赢了 277/520 局，胜率 53.3%（约 95% 区间 50.9%–55.7%），每局净升级 +0.113。在本地适配的南邮规则选手 v2 上，种子 980000–980155，旧版 235/312 胜，新版 237/312 胜。配对胜率差 +0.64 个百分点，区间 −2.34 至 +3.62，优势尚不明朗。南邮适配结果只适用于这里的动作顺序和规则。另试的 PerfectDan 公开 checkpoint 在 13 个换座种子上被旧版双上 26 次，本轮选 DanZero 作主对手。

## 2026-11-28 本地结果

参赛入口是牌桌实际调用的 `searchbot.bot.decide`。最终策略版本为 `022dc80`。两组各用 624 个新种子，打 2 到打 A 每种级牌 48 个种子，每局都由规则引擎校验动作。

| 对手 | 获胜局数 | 胜率（约 95% 区间） | 每局净升级（约 95% 区间） |
| --- | ---: | ---: | ---: |
| 优化前 `fad7344` | 727 / 1248 | 58.3%（56.0%–60.5%） | +0.423（+0.327 至 +0.519） |
| 第一轮 `da10f0b` | 661 / 1248 | 53.0%（50.7%–55.3%） | +0.125（+0.027 至 +0.223） |

净升级按本队赢时加 1–3、输时减 1–3 计算。区间以每个种子的两局平均值为样本，用均值 ±1.96 个标准误估算。对原版时，13 种级牌的净升级都为正。对第一轮时，打 8 和打 Q 两组为负。

```sh
# 在策略版本 022dc80 上复跑。两个对手各用独立种子段。
for level in $(seq 2 14); do
  sh games/guandan/scripts/arena.sh fad7344 48 "$((800000 + 48 * (level - 2)))" "$level"
  sh games/guandan/scripts/arena.sh da10f0b 48 "$((850000 + 48 * (level - 2)))" "$level"
done
```

对原版的分片启动后，最终代码将同一组实体牌的重复三带二候选合并。两种实现又在 27,413 个真实局面上逐动作对照，并另外比较了 1,443 次三带二候选列表，结果一致。对第一轮的整组对打直接使用最终提交。

## 怎么得到这版

- **开局领出**用掼蛋自对弈比较同一局面里的不同合法出法，以最终净升级差训练线性评分器。3,200 个训练种子生成 48,517 条比较，23 个系数能在本机复算。运行时只看自己的手牌和桌面公开信息。[训练脚本](scripts/train-opening.ts) · [方法参考：DouZero](https://proceedings.mlr.press/v139/zha21a.html)
- **拆牌和配合**会联合分配两张逢人配。三带二会比较带走哪一对后，剩牌还能分几手。对手报单时会用大单封口，同点有不同花色可选时会保留能成同花顺的牌。
- **残局搜索**比较截住对手、保留手型和给对家送单或送对等候选。采样遵守公开的进贡、还贡和抗贡信息。整场打 A 时，搜索把过 A 和退回 2 算进收益。

在相同的 117 个残局上，用本机 Node 交替测新旧版本。单步耗时的中位数从 107 毫秒降到 8 毫秒，P95 从 244 毫秒降到 225 毫秒。桌面、360 和 412 像素两种手机视口另外各打完了一副。四场从 2 打到过 A 的整场检查覆盖 43 副牌、98 次进还贡和 3 次抗贡，用于验证完整流程。
