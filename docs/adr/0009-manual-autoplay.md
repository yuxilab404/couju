# ADR-0009 手动托管：玩家自己点托管，平台统一提供

状态：已采纳 · 2026-11-28

## 背景

Owner 要求"所有游戏都加个托管，人可以手工托管"。之前的托管只有一种：真人掉线 30 秒后由 bot 接手，人回来或自己出一手就收回（ARCHITECTURE §4.5）。朋友打牌时临时走开、接个电话、不想打这把了，都没法主动让 bot 接手。

托管是每个游戏都要的能力，按 AGENTS.md 归平台层，游戏模块不用改。它要在平台的中继消息里加一条（成员 → 房主），属于房间/中继协议的变化，所以写本文。

## 决定

1. **中继消息 `ToHost` 加 `{ k: 'auto'; on: boolean }`**：成员请求托管或取消托管自己的座位。只在对局中、发送者坐在这一局里时有效，否则房主只回一次 `sync`。
2. **房主循环**（`platform/src/host.ts`）多一个集合 `manual`：自己点了托管的座位。`hosted`（下发给大家显示"托管中"的座位）= 掉线托管 ∪ `manual`。
   - 点了托管的座位，人在线也一直由 bot 出；掉线了不再等 30 秒宽限，回来也不收回。
   - 收回托管的三种方式：点"取消托管"；自己出一手（和掉线托管一样，人动了就是要自己打）；这局结束。正在替他想的 bot 立即作废。
   - 下一局开始时清空：托管只管一局，不会一直替人打下去。
3. **交接**：`manual` 写进快照（`Checkpoint.manual`，可选字段），换房主后照样托管。旧快照没有这个字段按空处理，标了 `TODO(del-when)`。
4. **界面**（`platform/src/ui/Room.tsx`）：对局中坐在桌上的人，房间顶栏有"托管"按钮；托管中时牌桌上方出现提示条，带"取消托管"按钮。游戏画面照常显示，各游戏已有的"托管中"座位标签自然生效。
5. **积分照常计**：托管的人照样计输赢，和掉线托管一样（ADR-0007）。

## 为什么不用别的办法

- **每个游戏自己做托管按钮**：五个游戏各写一遍，而且 bot 调度在房主循环里，游戏模块碰不到。
- **托管时锁住游戏画面的操作**：要改每个游戏的画面，或者平台盖一层遮罩挡住牌桌；而"出一手就收回"已经是掉线托管的既有语义，沿用它，人想自己打直接打就行。
- **托管跨局保留**：人走开了，下一局一直由 bot 打，回来发现已经打了好几局。每局清空，想继续托管再点一下。

## 代价

- 旧版本房主收到 `auto` 会忽略，按钮点了没反应；房主和成员版本不同时页面已有"刷新一下"的提示。
- 托管和自己出手之间有竞态：bot 想好的一手和人点的一手同时到，房主按到达顺序处理，后到的那手被拒（"还没轮到你"），和现在掉线托管时一样。

## 什么时候重新考虑

- 实时游戏上线时：实时游戏的 bot 每 tick 出输入，托管切换的语义要随实时循环一起设计。
