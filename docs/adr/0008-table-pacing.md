# ADR-0008 牌桌节奏：游戏声明停顿，平台统一控制 bot 出手

状态：已采纳 · 2026-11-26

## 背景

Owner 试玩唬牌后反馈：AI 出牌太快，"秒出"，上一家出了什么得盯着看半天；整体动画太糙。查下来有两个原因：

1. bot 的"思考"延迟只有 0.5–1.1 秒，而且喊骗子翻牌那一下，规则在同一个动作里就发完了下一轮的牌，下一个 bot 一秒后就接着出，翻牌结果还没看清就被盖掉。
2. 画面没有任何过渡：牌出现、消失都是一帧完成，看不出"谁刚出了这手"。

第 2 点是游戏画面自己的事，在游戏模块和 `games/_kit/cards` 里补动画即可。第 1 点涉及"bot 什么时候出手"，这由平台的房主循环决定（ARCHITECTURE §4.3），游戏模块碰不到；而"哪个局面值得停一停"只有游戏知道。所以要在游戏接口上加一个能力，按 AGENTS.md 写本文。

## 决定

1. **`TurnRules.pause?(s): number`**：进入局面 `s` 后桌上要停多久（毫秒）。可选，不提供就是 0。平台夹到 [0, 10000]。
2. **平台怎么用它**（`platform/src/host.ts`）：
   - bot 出手延迟 = 这个局面剩下的停顿 + 原来的思考延迟。同一个局面里因为成员变化、托管切换重新安排 bot 时，只停剩下的部分，不重新停一遍。
   - 真人的倒计时顺延同样的时间，看动画不占出牌时间。
   - 剩下的停顿随视图下发（`GamePublic.pauseMs`），客户端换算成本机时刻 `settleAt`；结算弹窗等到这一刻再弹，不盖住最后一下的动画（比如决定胜负的那一枪）。
3. **停顿不进规则**：它只是节奏，不改变状态、不影响 `apply` 的结果，回放和交接都不需要它。新房主接手时从头停一次，代价只是多等几秒。
4. **bot 默认思考延迟从 0.5–1.1 秒调到 0.8–1.5 秒**，配合出牌飞入动画（约 0.4 秒），每一手都能看清是谁出的。
5. **唬牌**用 `pause` 给翻牌留出完整的时间线（喊骗子 → 一张张翻开 → 判定 → 扣扳机 → 枪响，3 张牌约 3.4 秒）。时间线写在规则模块的 `showdownTimeline` 里，画面和 `pause` 共用这一份，改一处两边一起变。斗地主、掼蛋暂时不需要停顿，只靠默认思考延迟和动画。
6. **通用动画放在 `games/_kit/cards`**：`FlyIn`（新的一手从出牌人那边飞到桌面）、`FlipCard`（翻牌）、`Hand` 的 `deal`（发牌依次落下）、`Pop`、轮到谁的呼吸光和最后 5 秒的倒计时提醒。系统设置了"减少动态效果"时全部跳过。平台房间页按局数给游戏画面换 key，新开一局时入场动画重新放。

## 为什么不用别的办法

- **平台对所有游戏统一停更久**：唬牌翻牌要 3 秒多，斗地主每手都停这么久会拖得很烦；哪个局面重要只有游戏知道。
- **在规则里拆出"翻牌后等待"阶段**，等一个超时动作再发下一轮：把表现节奏塞进了规则状态，回放、交接、测试都要多处理一个假阶段；真人也得等这个阶段过去才能操作。
- **只在客户端放慢画面**（收到新视图先排队慢慢播）：bot 在房主那边照样秒出，客户端的队列会越积越长，真人轮到自己时画面还停在几手之前，看到的和能操作的对不上。

## 代价

- 接口多一个可选函数；不写的游戏行为和以前一样（只是 bot 默认慢了一点）。
- e2e 打一局的时间变长（唬牌每次翻牌多 3 秒多）。

## 什么时候重新考虑

- 要做回放时：回放的播放速度可能想直接复用 `pause`，到时看是否要把它从 `TurnRules` 挪到更通用的位置。
- 实时游戏不走这套（它们没有"轮到谁"），以后实时游戏需要类似的"慢镜头"再单独设计。
