# ADR-0010 规则说明：每个游戏带一份，平台统一放入口

状态：已采纳 · 2026-11-28

## 背景

Owner 要求"所有游戏加一个展示规则的功能，尤其是掼蛋，把各个炸弹的大小、各种顺序都展示出来"。朋友凑局时常有人没玩过某个游戏，或者记不清掼蛋里同花顺和 6 张炸弹谁大、级牌排在哪。

规则是游戏自己的事，入口（按钮、弹窗、手机适配）是每个游戏都要的，按 AGENTS.md 归平台层。这要在 `GameDef` 上加一个字段，属于游戏模块与平台之间的接口变化，所以写本文。

## 决定

1. **`GameDef.rules: ComponentType<RulesProps<V, O>>`，必填。** `RulesProps` 是 `{ numPlayers, options, view }`：房间当前的人数和可选规则，以及对局中我看到的视图（等人时为 `null`）。必填是为了以后加的游戏也一定带规则。
2. **平台**（`platform/src/ui/Room.tsx`）在房间顶栏放"规则"按钮，等人和对局中都能点，弹窗里画游戏的 `rules` 组件。弹窗内容自己滚动，手机上占满宽度；点遮罩、"关闭"或 Esc 关掉。平台给弹窗里的 `h4 / p / ul / ol / table` 统一排版，游戏只管写内容。
3. **规则跟着规则代码走，不另抄一份。** 例牌在渲染时用游戏自己的牌型识别（`patterns.ts`）解析、排序，时间、牌数、弹膛数直接引用 `rules.ts` 里的常量；`howto.test.tsx` 检查例子真是标的牌型、炸弹表逐档压得过。规则改了，说明要么跟着变，要么测试红。
4. **按当前局面写。** 掼蛋对局中按本副的级牌画例子（级牌排在哪、配牌长什么样），房间设置（只打一副、打 A 几次不过）按建房时选的写。
5. `games/_kit/cards` 加 `CardRow`：一小排叠着的静态小牌，规则里举例用。

## 为什么不用别的办法

- **规则写成一段 Markdown 字符串，平台渲染**：画不了牌面，也没法按当前级牌、人数变化，还得引一个 Markdown 渲染器。
- **单独的规则页（路由）**：对局中点开会离开牌桌；弹窗盖在牌桌上，关了就回来。
- **做成可选字段**：新游戏容易忘带，玩家点不到规则。必填的代价只是每个游戏写一个组件。

## 代价

- 每个游戏多一个组件和一份测试；规则文字本身仍然是人写的，代码里改了规则但文字没改，测试只能抓住例牌和数字，抓不住描述。改规则时顺手看一眼 `howto.tsx`。

## 什么时候重新考虑

- 实时游戏上线时：规则里可能要放操作说明（按键、触屏手势），到时看 `RulesProps` 够不够用。
